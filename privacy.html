CP : All in One privacy policy

Effective October 21, 2026. Applies to version 2.0.0. Maintained through our GitHub repository.

CP : All in One shows programming contests, adds Google Calendar reminders, backs up accepted solutions to a selected GitHub repository, and saves local notes beside supported problem pages.

Information used

  • Contest schedule: The extension requests contest feeds from the configured backend. The hosting service can receive connection information such as IP address and request timing. The backend uses the address visible to it for an in-memory request rate limiter; it does not request GPS coordinates. No GitHub or Google account credentials are included in contest-feed requests. Hosting-provider access-log retention is governed by the provider and configured service settings.
  • GitHub: After you authorize the GitHub App, access and refresh tokens are stored in local extension storage restricted to trusted extension contexts. Tokens are used directly with GitHub for sign-in renewal, permitted repository discovery and solution uploads. GitHub repository owners/usernames and signed-in programming-site identifiers are used for repository selection and ownership checks. No app client secret is included in the extension. Choose one private repository; source is organized by platform and language. Notes/metadata uploads are off in this release.
  • Google Calendar: Chrome manages Google sign-in. The extension uses the calendar.events.owned scope to read and manage events on calendars you own, and normally writes to your primary calendar. Event API responses can include event titles, times, links and other returned fields. These responses are processed transiently to identify managed events and are not sent to our backend or GitHub. Local sync state retains calendar identifiers, operation counts and error messages; errors may include contest titles. The extension identifies its managed events to update or remove them; it does not intentionally modify unrelated personal events. No calendar-list or calendar-creation scope is requested. Independent Add to Google Calendar links open Google for you to create an event manually; those events are not automatically managed or removed by the extension.
  • Programming sites: Accepted-solution capture on LeetCode, Codeforces, AtCoder, CodeChef and CSES reads relevant question/submission details, source and signed-in identity where needed to exclude other users' submissions. Browser-managed site sessions can be used for same-site source requests; passwords and cookies are not exported to our backend. CSES capture is limited to owned accepted result pages, not question-sheet import.
  • Notes: On supported questions on those sites plus HackerRank, GeeksforGeeks, SPOJ, Kattis and HackerEarth, the extension reads the question URL/title and notes you type. Notes stay on this device and are reopened on their question pages. Existing review metadata is preserved locally. Notes are not automatically synchronized between devices or sent to maintainers.
  • Preferences: Non-secret preferences can use Chrome storage sync. Backup source, job history and notes use local storage/IndexedDB.

Retention and deletion

Local notes remain until you clear them or remove extension storage. Unsaved drafts are not durable across closing or reloading a tab. Pending and failed backup source remains locally until upload succeeds or you remove its queue record; successful upload deletes its local queued source. Successful job history older than 90 days by record creation time is eligible for periodic cleanup while Chrome runs. GitHub tokens remain until disconnection, invalidation or replacement; Google manages its token cache. Disconnecting does not delete notes or queue history. Removing a remote authorization requires using the provider account settings. Preferences stored with Chrome sync follow Chrome account synchronization and deletion settings; uninstalling is not a guarantee that synced preferences are erased everywhere.

GitHub files and Google Calendar events remain with those providers until deleted. Provider retention rules and backups may apply. Legacy profile registration retention cannot be verified from the extension alone; see below. For private deletion concerns, email buildgit17626@gmail.com without sending passwords, tokens, identity documents or private source code.

Removed profile sharing

Version 2.0 does not discover or collect public account profiles, ratings or solved counts for maintainers, and has no admin profile dashboard. Older installations with an optional sharing registration attempt authenticated withdrawal on upgrade and retry if the service is unavailable. The updated server rejects new profile registrations and retains only an authenticated withdrawal endpoint for old registrations. The prior policy specified a one-year retention limit for historical registrations. Actual deletion/expiry of those historical records must be confirmed against the deployed database; this release does not create new registrations.

Your controls

  • Connections are optional; Contests and on-page notes can be used without them. First-time setup can be deferred.
  • Disconnect GitHub or Google to remove local credentials and pause automatic actions. A request already in flight may finish. Revoke remote authorization in the provider's account settings.
  • Edit or clear local notes on their question pages. Remove queued backup records to delete their stored source. Existing GitHub files require deletion on GitHub.
  • Remove extension-owned calendar events through Calendar. This pauses calendar synchronization.
  • Uninstalling removes extension-local data; downloaded exports, remote GitHub files and Google events remain until you remove them.

Security and third parties

Requests use HTTPS. GitHub App tokens and Chrome-managed Google credentials are not sent to our contest backend. Permissions are limited to supported platform sites and required provider endpoints. The extension does not include advertising or sell personal information. It processes supported problem/submission URLs, page titles, submission identifiers, verdicts and timing to attach notes to questions and trigger solution backups. It does not maintain a general browsing-history log or track unrelated websites. GitHub, Google, programming platforms and hosting providers process requests under their own policies.

Data use and access

Data is used only to provide the features described here, troubleshoot user-reported failures, and protect the service from abuse. It is not used for targeted advertising, credit decisions, surveillance or generalized AI model training. Calendar data is not routinely reviewed by maintainers; any user-authorized troubleshooting must follow Google's Limited Use rules. Third-party transfers are limited to the requested provider functionality, hosting/service operations and applicable legal obligations.

Contact and changes

For private questions or deletion concerns, email buildgit17626@gmail.com. Public bug reports can use the repository issues. This policy will be updated when the extension's data practices change.

Google API Limited Use

The use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy and the Chrome Web Store User Data Policy, including the Limited Use requirements. Google data is used only to provide the calendar features you request.
